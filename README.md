# Лабораторная работа №4: CI/CD
**Выполнила: Чернова Анастасия, ИДБ-25-07**

## Описание

Этот репозиторий содержит пример настройки промышленного CI/CD пайплайна для C++ HTTP-приложения с использованием **GitHub Actions**. 

## Возможности

- Автоматическая сборка C++ проекта (CMake, Ninja, ccache)
- Юнит-тестирование (Google Test), интеграционное тестирование, нагрузочное тестирование (wrk)
- Статический анализ кода (clang-tidy)
- Сборка Docker-образа и публикация в GitHub Container Registry (GHCR)
- Автоматический деплой в **staging** окружение с сохранением логов и метрик
- Ручной **blue-green** деплой в **production** с возможностью выбора версии образа
- Откат до любой версии через отдельный workflow
- Уведомления и отчёты в виде артефактов GitHub Actions (без внешних сервисов)

## Как использовать

### 1. Автоматический CI/CD (staging)
При каждом push в ветки `main` или `develop` запускается workflow:
- Сборка и тестирование приложения
- Публикация Docker-образа с тегом `latest`
- Деплой в staging-окружение (контейнер `staging-app` на порту `8080`)

### 2. Ручной деплой в production
1. Перейдите на вкладку **Actions** → **CI/CD Pipeline** → **Run workflow**
2. Выберите ветку `main`, укажите версию образа (например, `latest`)
3. Нажмите **Run workflow**
4. Будет выполнен blue-green деплой на порту `8080` (контейнер `app-blue`)

### 3. Откат
1. На вкладке **Actions** выберите **Rollback** → **Run workflow**
2. Укажите версию (тег образа), на которую необходимо откатиться
3. Workflow остановит текущий `app-blue` и запустит указанную версию

### 4. Артефакты и мониторинг
После каждого запуска в разделе **Artifacts** сохраняются:
- Логи контейнеров (`staging-logs`, `production-logs`, `rollback-logs`)
- Метрики из эндпоинта `/metrics` (`staging-metrics`, `production-metrics`)
- Отчёт о выполнении (`notification-report-*.txt`)
